# Phase 6 — Master CV Blueprint

**Purpose:** Comprehensive source CV from which the five targeted CVs will later be derived.

**Target length:** **3–4 pages** initially. We allow the evidence to determine the final length rather than forcing two pages.

---

## PAGE 1 — PROFESSIONAL IDENTITY

### 1. Header

**Fields**

* Name
* Professional headline
* Location
* Email
* Phone
* LinkedIn
* Portfolio/GitHub where relevant

**Headline direction:**

> **Aircraft Systems Engineer | Aerospace R&D | UAS & Aircraft Integration**

We will finalize the exact headline from the database evidence before drafting.

---

### 2. Professional Profile

**~100–130 words**

Purpose: establish the professional identity immediately.

**Structure:**

1. Aircraft systems engineering identity
2. End-to-end systems lifecycle
3. Manned + unmanned aircraft experience
4. Hardware/software integration
5. R&D / experimental aerospace
6. Current target direction

**Source:** Phase 5 narrative + competency map, with factual claims verified against database.

---

### 3. Core Competencies

**~12–16 competencies maximum**, grouped by importance.

**Primary competency group**

* Aircraft Systems Engineering
* Systems Engineering
* Systems Integration
* Requirements & Architecture
* Verification & Validation
* Avionics / Embedded Systems
* UAS Development

**Secondary/specialist group** derived from competency map.

No proficiency bars, percentages, stars or self-assessed ratings.

---

# PAGE 2 — PROFESSIONAL EXPERIENCE

## 4. Professional Experience

This is the **dominant section of the CV**.

For each Experience:

### Experience header

* Organisation
* Role/title
* Location
* Dates

### Experience summary

**2–3 lines maximum**, only where useful.

### Selected evidence

**3–6 bullets**, selected from the database.

Each bullet should demonstrate one or more of:

* engineering responsibility
* technical complexity
* lifecycle ownership
* integration
* verification/testing
* R&D
* measurable outcome

### Selection principle

We do **not** reproduce every database activity.

We select the activities that collectively communicate the strongest version of the experience.

---

## 5. Selected Technical/R&D Projects

This section is **not a duplicate of Professional Experience**.

It exists for substantial technical work whose significance would otherwise be buried inside academic/student/R&D experiences.

For each selected project:

* Project name
* Organisation/context
* Date
* 2–4 evidence bullets

Selection comes directly from the database and competency map.

**Important:** We will determine the actual projects *after mapping the database*. We don't pre-decide them based on my assumptions.

---

Include the substantive teaching/academic roles from the database:

Each entry gets **1–3 bullets**, depending on significance.

This section is intentionally preserved because it becomes disproportionately valuable for the Academic/Research CV.

# What gets **excluded from the Master CV**

Even though it exists in the database:

* Generic soft skills
* Generic career objectives
* Every student project
* Every activity
* Minor training courses
* Irrelevant university leadership
* Duplicated technical evidence
* Claims unsupported by the database
* Narrative biography
* Self-congratulatory comparative claims
* Anything included merely to increase CV length

The **database remains comprehensive; the Master CV remains selective.**

---

# Evidence hierarchy

When deciding what occupies space, we use this hierarchy:

**1. Professional engineering work**
**2. Major R&D / technical projects**
**3. Research outputs**
**4. Academic/teaching experience**
**5. Education**
**6. Licences/certifications**
**7. Technical tools**

This does **not** mean lower sections are less important. It determines how much CV real estate they receive.

# The actual production workflow

Once this blueprint is approved, we do **not** start writing the CV immediately.

### Phase 6A — Evidence Mapping

Database → each Master CV section.

### Phase 6B — Content Selection

Decide exactly which experiences/projects/activities earn space.

### Phase 6C — Draft

Write the actual Master CV.

### Phase 6D — Evidence Audit

Every substantive CV claim gets traced back to the database.

### Phase 6E — Recruiter/ATS Review

Test discoverability, positioning, clarity and potential red flags.

### Phase 6F — Master CV V1

**Lock the parent document.**

Then—and only then—we derive the five targeted CVs.
